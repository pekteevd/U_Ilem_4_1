# У Илем 4.1: план функциональной проверки

Цель: проверить не только запуск страницы, но и связность игровых систем. До завершения первичного прогона контрольный HTML не изменять.

## Приоритет текущего этапа разработки

В первую очередь исправлять и проверять игровые механики в следующем порядке:

1. Надёжное сохранение поручений и подтверждение действий. «Утвердить» закрывает окно только после успешного сохранения; при ошибке окно остаётся открытым, причина показывается пользователю.
2. Реальный расход материалов при выполнении работ. Списание происходит по фактической потребности этапа, только после успешного выполнения; нехватка ресурсов блокирует работу.
3. Связь результата работы с конкретным объектом. Выполненный этап обновляет состояние именно выбранного объекта, а не общий или похожий объект.
4. Защита от повторного выполнения. Повторный клик, обновление страницы или повторная отправка запроса не должны повторно выполнять этап и списывать ресурсы.
5. Ollama. Проверить обнаружение/подключение локальной модели, отправку запроса, получение ответа, понятное поведение при недоступности сервера и отсутствие ложных подтверждений игровых действий.

Визуальную доработку водонапорной башни «Маяк» и отдельного склада отложить до завершения первичной проверки этих механик. Контрольную карту и контрольный HTML не менять.

## Критерии корректного выполнения операции

- Каждое поручение и каждый этап имеют устойчивый уникальный идентификатор.
- Состояние поручения, состояние этапа, остатки ресурсов и состояние объекта изменяются как одна логическая операция.
- Если операция не может завершиться, не должно оставаться частичного результата: нельзя отметить этап выполненным без списания требуемых ресурсов или списать ресурсы без фиксации результата.
- Успешное выполнение фиксируется один раз. Повторная отправка той же операции возвращает уже сохранённый результат или понятное сообщение, но не повторяет списание.
- После перезагрузки страницы сохранённые поручения, статусы объектов и складские остатки согласованы между собой.
- Ollama отвечает за диалоговую помощь и интерпретацию запросов, но не является источником истины для финансов, склада и статусов. Игровые операции подтверждаются самой игровой логикой и сохраняются до сообщения об успехе.

## 10. Итоговый протокол

Для каждого дефекта записывать: раздел и объект; точные шаги воспроизведения; ожидаемое поведение; фактическое поведение; ошибку Console/Network; критичность (блокер / высокая / средняя / низкая).

## Журнал изменений — 5 ноября 2026

### Внесено в рабочую ветку
- Добавлен локальный сервер `server.js` без npm-зависимостей.
- Добавлен запуск Windows через `start.bat`.
- Чат отправляет запросы через локальный сервер в Ollama (по умолчанию модель `qwen3:4b`).

- Выполнение поручения проверяет исполнителя, время и наличие всех материалов до изменения состояния.
- Материалы списываются при успешном выполнении поручения; состояние назначенного объекта обновляется.
- Добавлена защита от повторного выполнения поручения и строительного этапа.
- Рядом с маркером Маяка добавлен отдельный маркер «Общий склад». Фоновое изображение карты не изменено.
